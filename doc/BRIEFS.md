# 系统简报

简报是 Paperclip 原生的公司级能力，不依赖 `orialis-brief` 插件。公司侧栏的“简报”和项目的“简报”页签显示数据库中的正式报告。历史插件里的静态快照不自动当作正式报告导入。

## 生成与投送

在简报页配置本公司的秘书，然后点击“生成简报”。系统创建明确指派给秘书的生成任务，使用现有代理适配器、预算与运行控制。排队或正在运行不等于报告完成。秘书核实本公司/指定项目的实时任务、必要评论与文档，生成 Markdown 正文，使用本次运行身份向原生 API 投送，并读回确认。报告必须保留原始要求、当前进度、达成证据或缺口，以及确需用户处理的事项；任务状态、构建或运行成功不是用户验收证据。

既有每日秘书可继续原来的心跳频率，但需在其指令中明确投送 API。每日无变化可不重复发布。系统不会自行改动其他公司的代理或心跳。

## 数据与接口

- `brief_settings` 保存每家公司的秘书绑定。
- `briefs` 保存公司、项目、认证作者、生成任务、标题、Markdown 正文、来源、状态和归档时间。
- 归档时保存认证作者的姓名快照。删除普通代理后保留报告和历史署名，仅清空作者代理引用。
- `GET /api/companies/:companyId/briefs?projectId=...` 读取最近 100 份归档报告。
- `GET/PATCH /api/companies/:companyId/briefs/settings` 读取或设置秘书。设置秘书和请求生成须有董事操作权限及任务指派权限。
- `POST /api/companies/:companyId/briefs/generate` 请求公司/项目简报，返回 `202` 与生成任务 ID。
- `POST /api/companies/:companyId/briefs` 仅接受本公司的已配置秘书认证，提交 `{title,body,sourceRefs,projectId?,issueId?,status?:"published"}`。作者从认证身份取得。`issueId` 需属于本公司且指派给该秘书，同一任务重复投送复用已有报告。

所有读取和写入均校验公司边界，项目与生成任务也校验公司归属。秘书提交带运行身份以保留审计记录。接口失败须报告失败，不能用只写了任务评论代替数据库投送成功。

## 升级

数据库迁移 `0297_lonely_scarlet_witch` 仅新增简报及配置表、索引与外键。升级前备份当前数据库；迁移通过后验证健康状态。旧简报插件可禁用，旧插件项目页签链接会跳转到原生简报页。
